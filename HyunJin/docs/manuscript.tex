\section{Implement This Week}

\subsection{CoCo-Agent Conditional Decomposition (Paper 7)}
\begin{itemize}
\item \textbf{Minimal experiment design:} Add a special <op> token as a CoT prefix before the JSON block. Train on your existing SFT data with a new output template: <op>TYPE</op>\{"op":"TYPE","target\_id":"...","value":"..."\}. Compare exact match on a held-out validation split.
\item \textbf{Required code changes:} src/train.py: update output\_template, add op-token prefix loss weight $\times$2. src/inference.py: parse <op> tag first, use predicted op to constrain the candidate search space (e.g., for CLICK, skip all <input type=text> elements from candidate list).
\item \textbf{Failure risk:} If op prediction accuracy is already near-perfect in your data, decomposition adds no signal. Validate by checking how often op errors co-occur with target errors --- if correlation is low, skip.
\end{itemize}

\subsection{diff History Encoding (Paper 10)}
\begin{itemize}
\item \textbf{Minimal experiment design:} Implement Python difflib.unified\_diff over consecutive cleaned\_html strings in history. Tokenize and measure average input length reduction vs. baseline. Test on validation set with same Qwen3-8B checkpoint, no retraining needed.
\item \textbf{Required code changes:} src/preprocess.py: add build\_diff\_history(steps: List[str]) -> str function. Replace raw history concat with diff output. Add max\_context\_length guard to truncate oldest diffs first.
\item \textbf{Failure risk:} If your HTML is already heavily cleaned/pruned, diff may be near-empty and uninformative. Fall back to raw history for first 2 steps (no previous state to diff against).
\end{itemize}

\subsection{Best-of-K Inference with Consistency Guard (Paper 11)}
\begin{itemize}
\item \textbf{Minimal experiment design:} For each test sample, generate K=5 JSON outputs (temperature=0.7). Apply your existing Consistency Guard to each; count valid outputs. Select the most frequent valid (op, target\_id) combination. No model retraining required.
\item \textbf{Required code changes:} src/inference.py: wrap single-call generation with sample\_k(prompt, k=5). Apply consistency\_guard(output) to each. Implement majority vote over (op, target\_id) pairs. Log how often the voted output differs from top-1 greedy.
\item \textbf{Failure risk:} Inference cost $\times$5. Viable only if GPU budget allows. Mitigate by triggering K>1 sampling only when confidence of greedy output is below threshold (e.g., top-token logprob < -0.5).
\end{itemize}

\subsection{Draft-Conditioned Constrained Decoding (Paper 6)}
\begin{itemize}
\item \textbf{Minimal experiment design:} Integrate lm-format-enforcer or outlines library with Qwen3. Measure: (a) format error rate before vs. after, (b) exact match change. Validate that reasoning quality is preserved by checking intermediate <think> content length.
\item \textbf{Required code changes:} src/inference.py: detect boundary between <think>...</think> and the JSON block. Apply unconstrained decoding in <think> section; switch to JSON schema-constrained decoding after </think> token. Schema = \{"op": enum, "target\_id": string, "value": string\}.
\item \textbf{Failure risk:} Some constrained decoding libraries have poor performance with Qwen3 tokenizer. Test tokenization boundary alignment before full deployment.
\end{itemize}

\section{High Upside, Medium Risk}

\subsection{WEPO-style DPO Hard Negatives (Paper 1)}
\begin{itemize}
\item \textbf{Minimal experiment design:} For each SFT training sample, the gold candidate is the "chosen" response. Construct "rejected" responses by: (a) substituting the gold target\_id with the 2nd or 3rd closest DOM-neighbor candidate, (b) substituting with a same-tag element from a different page section. Train DPO on top of SFT checkpoint for 1--2 epochs.
\item \textbf{Required code changes:} src/train.py: add build\_dpo\_pairs(sample) that generates rejected completions. Implement DPO loss alongside CE loss with a mixing ratio ($\lambda_{DPO} = 0.3$ initially).
\item \textbf{Failure risk:} If your candidate set is already highly curated, distance-based negatives may be too easy and provide no gradient signal.
\end{itemize}

\subsection{Agent Workflow Memory Retrieval (Paper 3)}
\begin{itemize}
\item \textbf{Minimal experiment design:} Cluster your training trajectories by site + task-template into 50--100 workflows. At inference, retrieve the top-1 matching workflow by (site, history signature) similarity. Inject as a prefix block.
\item \textbf{Required code changes:} src/retrieval.py: add WorkflowIndex class. Index built offline. Injection prepended to similar-examples block.
\end{itemize}

\subsection{WebCoT Rationale Annotation (Paper 9)}
\begin{itemize}
\item \textbf{Minimal experiment design:} Use a larger teacher model (Qwen3-72B) to annotate 5--10K training samples with rationales. Fine-tune Qwen3-8B on these.
\item \textbf{Required code changes:} src/train.py: update data pipeline to include rationale prefix in output template.
\end{itemize}

\section{Rejection Filter --- 5 Low-ROI Directions}
\begin{enumerate}
\item \textbf{Visual Grounding:} Vision encoders add significant overhead; unless switching to vision-native agents, the ROI is low for HTML-rich pipelines.
\item \textbf{Online RL:} Requires complex sandbox and 100x compute; SFT/DPO has much more headroom at your current stage.
\item \textbf{World Models:} Transition-focused abstractions are complex and target planning horizon, not element selection.
\item \textbf{Tool-Use Abstraction:} Architectural pivot that invalidates training data and benchmarks.
\item \textbf{Generic Context Compression:} Diff-history is already a near-free, efficient solution for your specific needs.
\end{enumerate}
